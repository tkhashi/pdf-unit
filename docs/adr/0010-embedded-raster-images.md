# ADR 0010: 埋め込み画像は PDFium で抽出し、表示座標へ変換して配置する

- ステータス: 採用
- 日付: 2026-09-23(ページ回転への対応は 2026-09-25)
- 追記(2026-09-26): [0038](0038-migrate-to-pypdfium2.md) で、座標系の基準を「pdfplumber の表示座標(MediaBox 基準)」から、ページの表示範囲(CropBox と MediaBox の交わり)の左上原点に変えました。埋め込み画像の変換(`PageToDisplay`)はもともとこの基準で、線・文字も同じ基準になりました。
- 追記(2026-09-26): [0039](0039-embedded-images-as-outlines.md) で、UI は埋め込み画像の画像データを描き直すのをやめ、配置範囲の枠と、範囲内を不透明にした原本画像で表示するようにしました。配置情報の抽出(四隅・配置方法)は変わりません。

## コンテキスト

ベクターとは別にラスター(PDFに埋め込まれた画像)も読み取って再描画し、ラスター / ベクター / 両方で表示を切り替えたいという要件があった。pdfplumber は画像の配置は取れるが、画像データのデコード(フィルタ・マスク処理)を持たない。

実装中・実装後に次の障壁があった。

1. 回転した画像を PDFium の `get_bitmap(render=True)` で描画させると、端が欠けて絵柄が崩れた
2. 画像が元PDFと異なる位置・向きで描画された。問題のページは `/Rotate 90 / 270` 付きで、PDFium の画像座標(回転前のPDF座標)を `get_height()` で上下反転しているだけだったため、回転後の表示座標(pdfplumber の座標)と食い違っていた

## 決定

- PDFium のページオブジェクトを走査して画像を集める。Form XObject は自前で再帰し、親フォームの変換行列を合成する
- 四隅の座標は `FPDF_PageToDevice` で表示座標へ変換する。この関数はページ回転と MediaBox の原点を反映する。出力が整数なので、ページを100倍の解像度に写像して0.01pt精度を得る
- 配置方法を2通りに分ける
  - PDF座標で回転・せん断が無い画像(`placement = "bbox"`): `render=True` で透過マスク・反転を適用した見た目を得る。ページ回転に合わせて `PIL.Image.transpose` で回し、外接矩形に描く
  - 回転・せん断がある画像(`placement = "affine"`): 生の画素を返し、UI側で画像の左上・右上・左下を四隅に合わせるアフィン変換で描く
- 表示モード「ラスター / ベクター / 両方」は、描画とヒット判定の両方に効かせる

## 理由

- 端が欠ける `render=True` を回転画像に使わなければ、絵柄を崩さずに配置できる
- `FPDF_PageToDevice` による変換は、回転ページの画像で pdfplumber の `page.images` と0.002pt以内で一致した。自前で回転を計算するより PDFium と pdfplumber の解釈を揃えやすい

## 影響

- 回転・せん断された画像は透過マスク(SMask)が未適用
- 入れ子のフォーム自体が回転している場合、位置は正しいが絵柄はフォームの回転を反映しない
- 回転90 / 180 / 270° のテストPDFで、PDFium の描画と再配置結果の平均画素差は0.3程度
