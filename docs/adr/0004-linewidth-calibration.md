# ADR 0004: 線幅は参考実装の自動キャリブレーションで実描画の太さに補正する

- ステータス: 採用
- 日付: 2026-09-23
- 追記(2026-09-26): [0038](0038-migrate-to-pypdfium2.md) で、補正の元にする線幅を pdfplumber の報告値(`w` を実行した時点の値)から、PDFium で読んだ描画時の太さに変えました。補正の仕組みは変えていません。

## コンテキスト

拡大時にハイライトの幅が線の太さに追従しないと、どの線がハイライトされているか分からないと指摘された。ハイライト幅を線の太さに合わせようとしたが、pdfplumber の報告する linewidth は実際の描画太さと一致しなかった(参考図面では報告値1.5ptに対し実描画は約0.27pt)。

## 決定

- 参考実装 `ClassifierArchDrawingByJev/src/classifier_arch_drawing/calibration.py` を `src/pdf_unit/calibration.py` にほぼそのまま移植する(スキーマ型の import だけ差し替え)
- ページごとに補正係数(実描画太さ ÷ 報告値)を求め、描画太さ = max(linewidth × 係数, 0.15pt) とする
- 係数と算出方法はステータスバーに表示する

## 理由

- 参考実装は、原本画像上で孤立した直線の太さを実測し、報告値との比を外れ値に強い方法で推定する。同じ問題を既に解いているので再実装しない
- 参考図面での係数は ×0.18 で、CAD のペン幅テーブルがそのまま報告値に入っているケースに対応できる

## 影響

- `/lines` の初回計算に約1.4秒かかる(ページ単位でキャッシュ。キャッシュは [0019](0019-aws-deployment.md) で廃止し、毎回計算する)
- 係数はページ内で1つなので、「描画太さ」で集めた集合は必ず「linewidth」と同じになる。クリック巡回では同じ集合を飛ばす仕組み([0006](0006-click-property-cycle.md))で自動的に省略される
- 孤立した直線が少ないページでは算出できず、係数1.0(`fallback_no_samples`)になる
