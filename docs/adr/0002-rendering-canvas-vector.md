# ADR 0002: 再描画は Canvas へのベクター描画とし、原本画像は薄い下敷きにする

- ステータス: 採用(当初案「ラスター画像 + SVGオーバーレイ」を置き換え)
- 日付: 2026-09-23

## コンテキスト

当初は、PDFium で描画したページ画像(ラスター)を表示し、その上に透明なSVGで検出線を重ねてホバー判定・ハイライトに使っていた(ユーザーが選択した方式)。しかし次の問題が出た。

- 原本画像は最大400dpiのため、拡大するとぼやけ、細かい格子状の線群を判別できない
- 参考図面を調べると、間隔0.06ptで並ぶ1pt未満の極短線が5,731本あった。抽出漏れではなく(原本の黒画素のうち抽出結果で説明できないものは 122/319,472)、表示側の問題だった
- ユーザーから、検出した種類(line/curve など)ごとの色分けも求められた

## 決定

- 抽出した線・文字を Canvas 2D にベクターとして描画する。種類ごとに色を分ける(line 青、rect 緑、curve 紫、text 橙)
- 描画は「種類 × 描画太さ」ごとに `Path2D` をまとめ、パン・ズームのたびに数十回の `stroke` で済ませる
- 原本画像は下敷きとして残し、不透明度をスライダーで調整できるようにする(初期値20%。主張しすぎないようユーザー要望で30%から変更)
- 文字は画面座標で描く(pt のまま極小フォントを拡大すると描画が崩れるため)
- 最大ズームを40倍から400倍に上げる

## 理由

- ベクター描画なら任意の倍率で鮮明に表示でき、極細の線群も拡大して見分けられる
- 色分けは Canvas の描画色で自然に実現できる
- 原本を下敷きにすると、検出されなかった要素が原本の灰色として見えるので、抽出の漏れを目視で確認できる
- SVG で数万要素を扱うより、Canvas にまとめて描く方がパン・ズームが軽い

## 影響

- ホバー判定を SVG の `:hover` に頼れなくなり、JS で自前の判定を持つ必要が生じた([0003](0003-hit-testing.md))
- 線の太さは報告値ではなく実描画の太さで描く必要がある([0004](0004-linewidth-calibration.md))
- Canvas の画素サイズと表示サイズがずれると描画が引き伸ばされる問題が後に発生した([0012](0012-layout-and-canvas-resize.md))
