# ADR 0044: 塗りつぶしを線と分けて新しい種類(fill)として検出し、種類の色で半透明に塗って表示する

- ステータス: 採用([0038](0038-migrate-to-pypdfium2.md) の図形の分け方のうち、塗るだけのパスの扱いを変更)
- 日付: 2026-10-01

## コンテキスト

ある設備図面のページで、検出した rect の約7割と curve の一部の線幅が 2.473pt・1.767pt と異様に太くなっていました。原本を見ると、そのような太い線は描かれていません。

調べたところ、太くなっていたのはすべて、線を描かずに塗るだけのパス(`re f*` など)でした。このページには、そのようなパスが300個あり、すべて白で塗られています。

- 表の中の字の背景を白く塗って、下の線を隠す矩形(281個)
- 機器記号の円の中を白く塗って、下の線を隠す円(19個)。円の輪郭は別の線を描くパスです

このCADの出力は、線を必ず `0.12 0 0 0.12 0 0 cm` の中で描き、塗りは等倍の座標系で行います。線幅(`2.47336 w`)は等倍の座標系で設定されます。そのため、線は 2.47336 × 0.12 ≒ 0.297pt で描かれますが、塗りのパスでは同じ値が等倍のまま 2.473pt と換算されていました。

[0038](0038-migrate-to-pypdfium2.md) では pdfminer と同じ規則で図形を分けており、pdfminer は塗りだけのパスも rect/curve にします。そのため、線として描かれない塗りの範囲にも線幅が付き、太い線として表示されていました。塗りだけのパスは線を描かないので、その線幅はどの線の太さでもありません。また、色も線の色(`FPDFPageObj_GetStrokeColor`)を返しており、実際に見える塗りの色とは違っていました。

## 決定

- **検出**: PDFium の `FPDFPath_GetDrawMode` で、パスが塗るか・線を描くかを調べます
  - 塗るパスは、塗りの範囲をパスごとに1件の fill として返します(`/api/page/lines` の `fills`)。塗りの規則はパス全体(全サブパス)にかかり、サブパスに分けると穴の扱いが変わるため、サブパスには分けません
  - 塗るだけで線を描かないパスは line/rect/curve にしません。線幅補正の実測の対象(rect・line)からも外れます
  - 線と塗りの両方を行うパス(`B` 等)は、これまでどおり線(line/rect/curve)にし、さらに fill にもします
- **fill の属性**: 次の値を持ちます
  - `d`: 全サブパスの SVG path
  - `polylines`: 閉じた折れ線(ベジェは8分割。開いたサブパスも塗りと同じように始点へ戻して閉じる)
  - `fill_rule`: `nonzero` / `evenodd`
  - `linewidth`: 塗るときに設定されていた線幅を、線と同じく描画時の CTM の拡大率で換算した値
  - `color`: 塗り色(`FPDFPageObj_GetFillColor`)
  - `bbox`: 折れ線の外接矩形
- **属性パネル・クリック巡回**: 種類 → 線幅 → 色 → 濃淡。線は描かれないので、描画太さは示しません。線とは別の種類として巡回します(同じ線幅の線を含めません)
- **表示**: 本来の塗り色によらず、種類の色(シアン `#0891b2`)を不透明度30%で、要素ごとの塗りの規則に従って塗ります。埋め込み画像の上、線・文字の下に描きます。ホバーは赤で塗って縁取りし、選択は黄の縁取りのうえに種類の色で塗り直します
- **ヒット判定**: 塗りの範囲の内側(塗りの規則で穴になる部分は除く)なら距離0、外側なら縁までの距離とし、文字・画像と同じく優先度を下げます(許容距離の0.75倍。文字は0.5倍なので、字の背景の範囲では文字が選ばれます)
- 要素の通し番号は、既存の要素の番号を変えないよう、線・文字・画像の後に fill を並べます

## 理由

- 塗りだけのパスを線として扱うと、描かれない線に太さが付き、線の太さの分析を誤らせます。一方で、捨てると「線を隠している白い範囲」が分からなくなります。そのため、別の種類として残します
- 白い塗りを本来の色で描くと背景に紛れて見えません。そのため、種類の色で半透明に塗ります。半透明なので、下の線や原本画像も透けて見えます
- 塗りの規則が違う要素や、重なる要素を1つのパスにまとめて塗ると、重なりが穴になるなど結果が変わります。そのため、線のように太さごとにまとめず、1件ずつ塗ります
- 線と塗りの両方を行うパスは、線も塗りの範囲も実際に描かれるので、両方として検出します

## 影響

- 線を描かないパスが line/rect/curve から除かれるので、そのようなパスを含むページでは件数・通し番号・クリック巡回の集合が変わります。上記のページでは、rect が 381→103件、curve が 632→610件になり、fill が300件になりました
- 線幅補正の実測の対象から塗りだけの矩形が外れるので、そのようなページでは補正係数が変わる可能性があります
- 塗りと線の両方を行うパスは、line/rect/curve と fill の2件になります(pdf-lib の色を指定しない矩形など)
- fill は1件ずつ塗るため、塗りの多いページ(べた塗りのハッチング等)では再描画が遅くなる可能性があります。問題になったら計測してから対策を検討します
- `scripts/compare_dumps.py` は `fills` も比べます(以前のダンプには無いので0件として扱います)
