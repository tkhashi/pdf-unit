# ADR 0017: ツールチップは自前で表示し、ツールバーはカテゴリで区切って状態を直接見せる

- ステータス: 採用([0016](0016-toolbar-tooltips-and-tristate.md) の補足の表示方法を置き換え)
- 日付: 2026-09-25

## コンテキスト

[0016](0016-toolbar-tooltips-and-tristate.md) でツールバーの補足をブラウザ標準のツールチップ(`title` 属性)で実装したが、ユーザーから次の指摘を受けた。

- ツールチップがどれも出てこない
- ヘルプアイコンはマウスを乗せると `?` のカーソルになるが、ヘルプ内容が表示されない
- 「PDFを開く」は「開く」でよい
- ベクター / ラスター / 両方 は、3つのうちどれかを選ぶセグメントボタンにしてほしい
- ツールバーはカテゴリごとに「|」で区切ってほしい
- ページ選択のプルダウンは無くてよい。開いているPDFのファイル名と「〇〇 / ✗✗ ページ」を小さく表示すればよい

ヘルプの `?` も `title` 属性に頼っており、カーソルが変わるのは CSS の `cursor: help` によるものだった。ブラウザ標準のツールチップは表示まで約1秒の遅延があり、ウィンドウにフォーカスが無いときや埋め込み型のブラウザなど、環境によっては表示されない。

## 決定

- 補足文は `title` ではなく `data-tip` 属性に持たせ、自前のツールチップ要素(`#tip`)で表示する
  - 表示: マウスを乗せて250ms後。キーボードでフォーカスしたときも表示する
  - 非表示: 要素から外れたとき、クリック・ホイール操作時
  - 位置: 対象要素の直下(入らなければ上)。左右は画面内に収める
  - イベント委譲で1か所にまとめる。動的に変わる補足(原本の濃さ・線幅補正の理由・開閉バーの向き・種類ごとの件数)は `setTip()` で更新し、表示中なら内容も差し替える
- ヘルプ `?` はボタンにし、マウスを乗せると操作説明を表示する。クリックまたは Enter で表示を固定し、もう一度クリックするか Esc、外側のクリックで閉じる
- 「PDFを開く」を「開く」に改名する
- 表示切替は、枠でつながった3つのボタン(両方 / ベクター / ラスター)のセグメントコントロールにする。選択中を塗りつぶし、`role="radiogroup"` と `aria-checked` で状態を示す
- ページ選択のプルダウンを廃止し、「開く」の横にファイル名(長ければ省略、全体は補足に表示)と「3 / 108 ページ」を小さく表示する。ページの移動はサムネイル一覧で行う。内部のページ状態はプルダウンの値ではなく `currentPage` 変数で持つ
- ツールバーを縦線で区切る: アプリ名 | 開く・ファイル名・ページ | 表示切替 | 凡例 | 原本の濃さ | 線幅補正 … `?`。文書を開く前は、文書に依存する項目とその区切りを出さない

## 理由

- 自前のツールチップなら環境に依存せず、遅延・位置・見た目を制御できる。`data-tip` に移せば標準ツールチップとの二重表示も起きない
- 長い操作説明はマウスを乗せ続けるのが負担なので、ヘルプだけは固定表示できるようにした
- セグメントボタンは、選べる3つの選択肢と現在の選択が常に見え、1クリックで切り替えられる。プルダウンは開くまで選択肢が見えない
- ページ移動の手段がサムネイル一覧と重複していたため、プルダウンは現在位置の表示に置き換えた

## 影響

- サムネイル一覧を閉じている間は、ページを移動する手段が無い(一覧を開いて選ぶ)
- ヘルプの文言は従来どおり index.html(`#help` の `data-tip`)に持つ
