# ADR 0046: 塗りつぶしに掛かるクリップを返し、クリップの内側だけを塗って表示する

- ステータス: 採用([0044](0044-fill-regions.md) の塗りつぶしの表示・ヒット判定を変更)
- 日付: 2026-10-01

## コンテキスト

[0044](0044-fill-regions.md) で塗りつぶし(fill)を表示するようにしたところ、ある建築図のページで、左側に原本には見えない大きな円(直径約320pt)が表示されました。

調べたところ、この円は実際に塗られていましたが、クリップパスで大部分が切り取られていました。

- 同じ中心で塗り色が rgb(212)〜(224) と少しずつ変わる円が49個あります。CAD がグラデーションを同心円の重ね塗りで表したものです
- それぞれの円に、幅74pt・高さ0.7pt 程度の細い帯などのクリップが掛かっています。原本では、洗面カウンターや浴室の薄い灰色の陰影として、クリップの内側だけが見えます

抽出はクリップを考慮しておらず、円全体を fill として表示していました。このページでは、塗りのパス1,773個のうち541個で、クリップの範囲が外接矩形の半分に満たない状態でした。

PDFium の API について、次のことを確かめました。

- `FPDFPageObj_GetClipPath` は、CTM を掛けた後の座標でクリップを返します。Form XObject の中のオブジェクトでは、フォームの中の座標(フォームの `/Matrix` を含み、外側の `cm` は含まない)で返します
- Form XObject 自体に掛かるクリップは、中のオブジェクトの `GetClipPath` には含まれません
- 複数のクリップは、PDFium が可能な範囲で1つにまとめます(矩形どうしは共通部分の矩形になります)。また、図形を完全に含む矩形のクリップは、効果が無いので省かれます
- クリップの塗りの規則(`W` / `W*`)を返す API はありません

## 決定

- **サーバー**: 塗りつぶしに掛かるクリップを返します
  - 塗るパスのクリップと、外側の Form XObject に掛かるクリップを重ね、表示座標(外側のフォームの行列とページ行列を掛ける)に直します
  - 同じクリップは多数の図形が共有するので、`/api/page/lines` の `clip_paths`(`{d, polylines}`)にまとめます。fill の `clip` には、その添字を入れます
  - 塗られる範囲は、fill の範囲と、すべてのクリップの共通部分です
  - クリップの塗りの規則は、非ゼロ回転数とみなします
- **UI**
  - fill の塗りと縁取り(ホバー・選択)は、Canvas の `clip()` で、すべてのクリップの内側だけに描きます
  - ヒット判定は、すべてのクリップの内側にある点に限ります
  - 属性パネルに「クリップ: あり」を表示します
  - bbox はクリップする前の範囲のままにします
- 線(line・rect・curve)のクリップは、今回は扱いません(ユーザーの指定で、fill だけを対象にしました)

## 理由

- 原本と同じ範囲だけを塗れば、見えない形が表示されることはありません
- クリップを外すと完全に隠れる fill だけを除く方法もありますが、一部だけ見える fill は形全体が表示されたままになります。そのため、クリップの形をそのまま使います
- クリップの共通部分を多角形の演算で求めると、誤差や計算量の問題が出ます。Canvas の `clip()` とヒット判定での内外の判定なら、形をそのまま扱えます

## 影響

- 上記のページでは、クリップは22種類(合計168点)で、669件の fill が参照します。応答の大きさはほとんど変わりません
- `W*`(偶奇規則)のクリップで、穴のある形や自己交差する形の場合、塗る範囲が原本と異なることがあります(PDFium の API の制約)
- 文字によるクリップ(文字の描画モード 4〜7)は考慮しません
- 線はクリップの外にはみ出す部分も表示するので、同じような「見えない線」は残りえます
- クリップの外にしかない fill も、件数には含まれます(画面には描かれず、ホバーでも選ばれません)
- グラデーションを重ね塗りで表した部分は、半透明の塗りが重なって濃く表示されます
