# ADR 0031: React 移行で機能が変わっていないことを、旧UIとの並走比較(Playwright)で確かめる

- ステータス: 採用
- 日付: 2026-09-26

## コンテキスト

React への移行([0027](0027-frontend-react-typescript.md))の要件は「機能を変えない」ことで、見た目はピクセル単位で一致しなくてよい(整っていることを優先する)ものでした。旧UIには自動テストが無く、目視の確認だけでは、ヒット判定の走査順・選択の巡回・古い応答を捨てる条件・ツールチップの遅延といった細かな挙動の違いを見落とすおそれがありました。

## 決定

- 純粋関数に切り出したロジック(`web/src/domain/`)と reducer は Vitest で検査する
- 旧UI(比較の基準 `BASE_REF`、既定は計測を入れた `7acb834` の `index.html`)と新UIを Playwright で並走させ、同じ操作をして結果を比べる(`web/e2e/parity.spec.ts`、`pnpm e2e:parity`)
  - API サーバーは1つだけ(既定 `127.0.0.1:8765`)。旧UIは `git show` した `index.html` と同梱の pdf-lib を、新UIは `--mode e2e` のビルド(`window.__pdfUnit` で状態を読める)を `page.route` で配信し、`/api/*` だけを中継する。差分は UI 由来だけになる
  - 比べるもの: 状態(ホバー・選択・表示変換・原本画像の解像度段階・表示対象)、属性パネル・凡例・ステータス・ページ表示・ツールチップの文字列、title、API の呼び出し(パス・クエリ・送ったPDFの SHA-256)、`console.debug` の計測ログの書式、Canvas(線・文字・画像の層とハイライトの層)の画素、ブラウザ内で2万点×4倍率のヒット判定
  - 見た目の違いでヘッダーの高さが変わると全体表示の倍率が変わるため、表示領域の大きさを揃えてから比べる。pdf-lib は切り出したPDFに作成日時を書くため、時刻を固定する
  - 合成PDF(`web/e2e/fixtures.ts`。線・矩形・曲線・文字・PNG/JPEG・回転画像・/Rotate・CropBox・25ページ・4MB を超えるページ・暗号化・PDFでないファイル)を使う
- 新UIだけの基本動作の E2E(`web/e2e/app.spec.ts`)は常に実行できるようにする

## 理由

- 旧UIそのものを基準にすれば、仕様書(README)に書かれていない細かな挙動も含めて比べられる
- 定数を1つ変えると比較が失敗することを確かめ、検出できることを確認した

## 影響

- 比較で見つかった旧UIの次の癖は、機能の変更になるため今回は変えずに残した(別途直すかを判断する)
  - 最初に文書を開くときは、ステータス欄が文書を開くまで表示されないため、「読み込み中...」や読み込みエラーが画面に出ない
  - 暗号化されたPDFのエラーは「暗号化されたPDFは開けません」と出す意図だったが、pdf-lib の `EncryptedPDFError` が `instanceof` で判定できない(ES5 に変換された Error の派生クラスのため)ことから、実際には「PDFを読み込めません(…encrypted…)」になる
  - 同じファイルをもう一度選んでも反応しない(ファイル選択の値を消さないため)
  - 図面表示領域の外へ PDF をドロップすると、ブラウザがそのPDFを開く
- 比較テストは旧UIを `git show` で取り出すため、`BASE_REF` がリポジトリに存在する必要がある。UI の機能を意図して変えた後は、比較の基準も合わせて更新するか、比較テストの役目を終えたものとして `app.spec.ts` 側へ期待値を移す
