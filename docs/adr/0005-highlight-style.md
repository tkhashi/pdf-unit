# ADR 0005: ハイライトは幅をズームに連動させ、選択時は他要素の減光と黄色の縁取りで示す

- ステータス: 採用
- 日付: 2026-09-24(画像の枠は 2026-09-25 に変更)

## コンテキスト

ハイライトについて、段階的に次の指摘を受けた。

1. 拡大時に幅が追従しないと、どの線がハイライトされているか分からない
2. 全体表示のとき、ハイライトが太すぎてどれが選ばれているか分からない
3. 元の線が青系なのに、グループ選択のハイライトが水色で見分けにくい
4. 隙間なく並んだ5枚の埋め込み画像(分割された表の画像)をクリックすると、1つの塊としてハイライトされる

## 決定

- ハイライト幅 = 線の描画太さ + 片側のはみ出し幅 × 2。はみ出し幅は `clamp(ズーム倍率, 1, 3)` 画面px(縮小時は1px、拡大すると最大3px)
- クリック選択中は、描画全体を20%の不透明度に減光する。選択した要素は本来の色で描き直し、黄色(`rgba(250,204,21,0.85)`)で縁取る
- ホバーは赤(`rgba(239,68,68,0.6)`)。種類の色(青・緑・紫・橙・灰)と選択の黄のどちらとも区別できる
- 画像のハイライトは薄い塗りと、画像の内側へ寄せた枠線で描く。描画順は「画像の描き直し → 枠」とする

## 理由

- 画面px固定だと、拡大すると線の方が太くなりハイライトが埋もれ、縮小すると周囲の線まで覆う
- 色相だけで区別しようとすると、種類の色と必ずどれかが近くなる。減光で選択要素を浮かせれば色相に依存しない
- 画像の不具合は、描き直した不透明な画像が塗りと枠の内側半分を隠し、外側へはみ出した枠だけが隣同士でつながっていたことが原因だった。内側に枠を描けば隣接画像の間に隙間ができる

## 影響

- 選択の有無で下層(減光)も描き直す必要があり、クリック・Esc で全体を再描画する
- 選択要素を描き直すため、グループ用の `Path2D` を「種類 × 描画太さ」ごとに作っている
