# ADR 0003: ホバー判定は空間インデックス付きの最近傍探索で行う

- ステータス: 採用
- 日付: 2026-09-23

## コンテキスト

当初は各線に画面上6px幅の透明なSVGストロークを重ね、CSS の `:hover` で判定していた。ユーザーから「細かい線が集まっているところは判定が厳しい」と指摘された。重なった透明ストロークのうち最前面のものが取られるため、カーソルに一番近い線が選ばれていなかった。

## 決定

- 線分を8pt四方のセルに登録する空間インデックスを作り、カーソル周辺のセルだけを調べる
- 候補の条件: 線の縁(中心線から描画太さの半分)までの距離が画面上8px以内
- 候補の中から、中心線がカーソルに最も近いものを選ぶ(縁までの距離ではなく中心線の距離で順位付け)
- curve のベジェ曲線はサーバー側で8分割の折れ線にして判定に使う(描画は元のベジェのまま)
- 文字と画像は枠(画像は回転を考慮した四隅の多角形)までの距離で判定し、枠内でもペナルティ(許容距離の0.5倍 / 0.75倍)を加えて、重なる線を優先する

## 理由

- 許容距離を画面px基準にすると、拡大するほどページ上の判定範囲が狭くなり、密集部も選び分けられる
- 縁の距離だけで順位付けすると、描画上重なった極細線はどれも距離0になり決まらない。中心線の距離なら1本に決まる
- 回転画像を外接矩形で判定すると、画像の外(矩形の角)でも反応してしまうため多角形で判定する

## 影響

- 参考図面の line 9,564本すべてで、各中点での判定が自身または同じ点を通る線を返すことを確認した(ズーム1/20/100倍)。1回の判定は約0.03ms
- 判定ロジックは `index.html` の `pick()` に集約されている
