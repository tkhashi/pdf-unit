# ADR 0013: ページ一覧のサムネイルは専用APIで遅延読み込みし、本体ページの表示を優先する

- ステータス: 採用(API の形式・キャッシュ・同時要求数は [0019](0019-aws-deployment.md) で置き換え。10ページ単位のバッチ取得に変更し、キャッシュは廃止)
- 日付: 2026-09-25

## コンテキスト

108ページのような図面では、プルダウンだけでは目的のページを探しにくい。一般的なPDFリーダーのように各ページのサムネイルを見ながらページを選びたいという要件があった。サムネイルは線検出していない元PDFの画でよい。

## 決定

- サーバーに `GET /api/documents/{id}/pages/{n}/thumb.png?width=` を追加する
  - PDFium でページ幅が指定幅になる倍率で描画する(ページ回転は PDFium が反映)
  - 既存の原本画像APIは dpi 指定で最小36dpiのため、大判図面の160px幅(約10dpi)には使えないので別関数にする
  - `_pdfium_lock` 内で実行し、サーバー側(512件)とブラウザ側(`Cache-Control: max-age=3600`)でキャッシュする
- UI は左に縦スクロールの一覧を置き、ヘッダーのボタンで開閉する(状態は localStorage に保存)
  - 開閉ボタンの位置は [0015](0015-ui-labels-and-controls.md) で一覧の左に隣接する縦ボタンへ変更した
- 読み込み制御
  - `IntersectionObserver` で表示範囲(前後300px)に入ったものだけを要求する
  - 同時要求は2件まで
  - 本体ページの線データ取得中は新規要求を止め、完了後に再開する
- 現在ページは枠で強調し、プルダウンから切り替えた場合も一覧をスクロールさせて追従する(端に貼り付かないよう `scroll-margin` を付ける)

## 理由

- サーバー側の PDFium 処理は直列([0011](0011-pdfium-thread-safety.md))なので、108ページ分を一度に要求すると本体ページの表示が待たされる。見えている分だけを、本体を優先して取得する
- 読み込み前から `aspect-ratio` で枠の大きさを決めておけば、読み込みに伴って一覧がずれない

## 影響

- 初期表示で読み込まれるのは見えている8件程度
- 線データ・原本画像・サムネイルの計50件を同時に要求しても全件成功することを確認した
