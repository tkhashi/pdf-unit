# ADR 0008: 文字は単語単位で扱い、描画サイズはフォントサイズを逆算して求める

- ステータス: 採用
- 日付: 2026-09-23(サイズ算出は 2026-09-25 に修正)

## コンテキスト

文字もホバー・クリックの対象にしたいという要件があった。その後、特定の図面だけ再描画した文字が極小サイズになると指摘された(ハイライトの大きさは正しかった)。

当初は参考実装 `render.py` と同じく、文字の変換行列(pdfminer の `matrix`)の長さ `hypot(a, b)` を文字サイズとしていた。しかし pdfminer の `matrix` はフォントサイズ(PDFの `Tf` 命令で指定する値)を含まない。

- 多くのPDFは `Tf=1` で行列側に拡大を持たせるので、行列の長さがそのまま文字サイズになる
- 問題の図面は行列がほぼ単位行列で `Tf` にサイズを直接指定していたため、5〜13ptの文字が約1ptで描かれていた

## 決定

- pdfplumber の `extract_words`(フォント名・サイズ・色が変わる箇所で区切る)で単語単位にまとめ、単語の外接矩形をヒット判定・ハイライトに使う
- 描画は文字ごとに行い、位置と回転は `matrix` から求める
- フォントサイズ F は、文字空間での矩形(幅 = `adv`、高さ = F)を行列で写した外接矩形の式から逆算する
  - 幅 = |a|·adv + |c|·F
  - 高さ = |b|·adv + |d|·F
- 描画サイズ = F × 縦方向の倍率 `hypot(c, d)`。横方向だけの伸縮(長体・平体)は `hypot(a, b) / hypot(c, d)` で反映する

## 理由

- 外接矩形はフォントサイズを反映して計算されている(ハイライトが正しかったのはこのため)ので、そこから逆算すれば行列の持ち方に関係なく正しいサイズが得られる
- 回転した文字でも、行列成分の大きい方の式を使えば解ける

## 影響

- 3図面で描画サイズと文字の高さの比が0.999〜1.011に収まった。従来の図面や斜め文字(10° / 64° / -29°)は以前と同じ値
- 再描画は sans-serif で描くため、元フォントとは字形・字幅が異なる
