# ADR 0025: 線幅補正の孤立判定を格子状の空間索引で行う

- ステータス: 採用
- 日付: 2026-09-26

## コンテキスト

線幅補正(ADR 0004)は、ほかの図形と重ならない「孤立した」直線をサンプルに選び、原本画像で太さを実測します。孤立しているかの判定(`_select_isolated_straight_samples`)は、候補の線分ごとに、ページ上のすべての図形の bbox と重なりを総当たりで調べていました。処理量は「候補の線分の数 × 図形の数」に比例し、途中で打ち切ることもありませんでした。

ADR 0023 の計測で、実際の図面 PDF 3種(A1 判の図面1ページ、軽量な図面67ページ、線の多い図面46ページ)を調べたところ、この判定が `/api/page/lines` の所要時間の 69%・26%・69% を占めていました。線が約4.7万本の A1 判のページでは重なり判定が約1.6億回呼ばれ、判定だけで約10秒、最も遅いページでは約17秒かかっていました。線の多い図面では、全46ページで候補が算出に必要な数に届かず、結局は補正なしになるにもかかわらず、この時間を使っていました。

## 決定

- 図形の bbox を、ページの長辺を128等分した格子に登録する索引(`_BBoxGrid`)を作ります。各線分の近傍と同じ格子に載っている bbox だけを調べ、重なるものが1つ見つかった時点で打ち切ります。
- 重なりの判定式(`_bbox_overlaps`、辺が接する場合も重なりとみなす)と、自分と同じ bbox を除く条件は変更前のままです。
- 256個を超える格子にまたがる bbox(ページ全体を囲む枠など)と、非有限の座標を含む bbox は格子に載せず、毎回すべて調べます。4096個を超える格子にまたがる問い合わせは、索引を使わずに総当たりで調べます。

## 理由

- **結果が総当たりと完全に一致する**: x 方向で重なる2つの区間には共通の点 x があります。`floor(x / 格子の一辺)` は x について単調(正の数での除算は丸めを含めて単調)なので、その点の格子は両方の格子範囲に含まれます。y 方向も同じです。したがって、重なる bbox は必ず問い合わせ範囲の格子に載っていて、候補から漏れません。判定式は同じなので、選ばれるサンプルとその順序は変わりません(ADR 0023 の「出力を変えない」方針)。
- **検証**: 3種の PDF の全117ページについて、変更前と変更後の関数を同じページに適用し、選ばれた線分(座標・線幅・順序)がすべて一致することを確かめました。API の応答ボディ105件(ADR 0023 と同じページ)もバイト単位で一致しました。
- **効果**(手元での計測): 判定の合計時間は全117ページで 72.7秒 から 1.8秒 になりました。`/api/page/lines` の所要時間は次のとおりです。
  - A1 判の図面: 14.2秒 → 4.7秒
  - 線の多い図面: 全ページの合計 70.2秒 → 23.2秒、最も遅いページ 18.5秒 → 2.3秒
  - 軽量な図面: 全ページの合計 45.9秒 → 38.3秒(中央値 0.40秒 → 0.26秒)
- **格子の大きさ**: 孤立判定の近傍は線分の外接矩形を線幅(1pt以上)だけ広げた範囲なので、格子はページの長辺の1/128(A1 判で約18pt)とし、短い線分の問い合わせが数個の格子で済むようにしました。長い線分でも問い合わせる格子は高々数百個です。

### 採らなかった案

- **R-tree などのライブラリを使う**: 依存が増え、Lambda の zip も大きくなります。格子で十分に速くなったため見送りました。
- **候補が必要数に届かないと分かった時点で打ち切る**: 候補の数は実測前には分からず、打ち切りの条件を加えると結果が変わらないことの説明が複雑になります。索引だけで判定がほぼ無視できる時間になったため見送りました。
- **判定を近似する(bbox を粗く丸める、一部の図形だけを調べる)**: 選ばれるサンプルが変わり、補正係数が変わりうるため採りません。

## 影響

- 線幅補正の結果(`linewidth_scale`・`calibration`)は変わりません。
- `/api/page/lines` で最も時間がかかる処理は、pdfminer によるページの解析(`parse`)になりました。解析はライブラリの処理そのものであり、出力を変えずに速くする手段は今のところありません。
- 索引の分、一時的にメモリを使います(bbox への参照を格子ごとに持つ程度で、4.7万本のページでも数MB)。
