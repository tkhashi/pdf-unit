# ADR 0038: PDF の読み取りを pdfplumber から pypdfium2 に移行する

- ステータス: 採用([0037](0037-pdfium-migration-research.md) の提案を採用。[0023](0023-performance-measurement.md) の「出力を変えない」の例外。[0011](0011-pdfium-thread-safety.md) のロックの範囲、[0009](0009-cid-character-restoration.md)・[0018](0018-cid-restoration-rotation-and-validation.md) の cid 補完、[0010](0010-embedded-raster-images.md) の座標系の基準を置き換え)
- 日付: 2026-09-26
- 追記(2026-10-01): [0044](0044-fill-regions.md) で、塗るだけで線を描かないパスは line/rect/curve にせず、塗りつぶし(fill)として分けるように変えました。線を描くパスの分け方は変えていません。

## コンテキスト

`/api/page/lines` の処理時間の大半は、pdfplumber(内部の pdfminer.six)によるページの解析でした(A1 判・図形約4.7万個のページで 4.7 秒中 3.9 秒)。ADR 0037 の技術調査で、PDFium から pdfplumber の Page と同じ形のデータを作れば、既存の抽出処理をほぼそのまま使えて大幅に速くなることが分かりました。一方で、ADR 0023 の「出力をバイト単位で変えない」は満たせないことも分かりました。

ユーザーは移行を承認し、次の方針を決めました。

- 判断の基準は「後方互換性より、元の PDF の再現性」とする
- 座標は、PDFium の描画・埋め込み画像・UI のページ寸法と同じ CropBox 基準に揃える
- 単語へのまとめ(pdfplumber の `extract_words`)は取り込み、pdfplumber を依存から外す
- ToUnicode の無いフォントは近似判定で「□」にする
- 実装中に新しいトレードオフが見つかったら報告して判断を仰ぐ(下記の UTF-8 の CMap が該当し、既知の制約として受け入れた)

## 決定

1. **`src/pdf_unit/pdfium_page.py` の `PdfiumPage`** が、PDFium のページから `width`・`height`・`rects`・`curves`・`lines`・`chars`・`to_image()` を組み立てます。`extract_page_lines`・`calibrate_linewidth` はそのまま使い、`extract_page_texts` は引数からPDFのバイト列を外しました。
   - **座標**: ページの表示範囲(`page.get_bbox()`。CropBox と MediaBox の交わりで、/Pages から継承した CropBox も含む)の左下を原点とするページ行列を作り、上原点に直します。/Rotate の扱いと行列の掛け方は pdfminer と同じ式です。CropBox が MediaBox と同じで原点が 0 のページでは、以前と同じ値になります。
   - **数値**: PDFium の API は float32 を返すため、「float32 として同じ値になる最短の10進数」に戻してから float64 で計算します。PDF に書かれた数値(有効数字7桁まで)がそのまま復元されます。
   - **図形**: サブパスごとに分け、pdfminer と同じ規則で line/rect/curve に分けます。PDFium が閉路に足す「始点へ戻る点」は取り除きます。線幅は `w` の値に描画時の CTM の拡大率を掛けた、実際に描かれる太さです。色は PDFium が色空間を変換した RGB です。
   - **文字**: 文字の原点・行列・フォントサイズ・descent から外接矩形を作ります。送り幅はゆるい外接矩形から逆算し、フォントの幅を 1/1000 em の 0.1 単位に戻します。フォント名は、UTF-8 で読めれば str、読めなければバイト列のまま渡し、既存の `decode_font_names` で判定します。
   - **スレッド安全**: 図形と文字はコンストラクタ(ロックの中)で組み立て終えます。遅延評価はしないので、ロックの外で PDFium を呼ぶことはありません。
2. **ToUnicode の無いフォント**: pdfminer の `(cid:N)` を手がかりにした補完(`_restore_cid_chars`)をやめました。代わりに `_mark_unreadable` が、フォント単位で「よく使われる文字」が9割に満たなければ、そのフォントの全文字を「□」にします。PDFium には、Unicode に引けなかったかどうかの区別も CID の値も無いためです。
3. **server.py**: PDF は PDFium で開きます(開けなければ 400、ページが無ければ 404)。開いてから閉じるまでをロックの中で行い、閉じるのも try/finally でロックの中です。`/api/page/lines` は、1つの文書で図形・文字・線幅補正の描画・埋め込み画像を処理します。原本画像は PDFium で直接描画します(以前の `page.to_image()` と同じ描画設定)。埋め込み画像の bitmap は、PNG 化した後にロックの中で閉じます。
4. **依存**: pdfplumber を外し、pypdfium2 と Pillow を直接の依存にしました(Pillow は server が直接使っていましたが、pdfplumber 経由の推移的な依存でした)。版は 5.13.0 と 12.3.0 のままです。pdfplumber 0.11.10 の `utils/text.py`・`clustering.py`・`geometry.py`・`generic.py`・`_typing.py` は、変更せずに `src/pdf_unit/_vendor/pdfplumber/` に取り込みました(MIT、LICENSE.txt 同梱)。pdfminer を読み込む `utils/__init__.py` だけは、`extract_words` を公開するものに置き換えています。
5. **テスト**: `tests/`(pytest)を追加しました。合成PDFで、座標・回転・CropBox・線と原本画像の位置の一致・図形の分類・`v`/`y`・線幅・色・Form XObject・横倍率・CMap で符号化した本文・フォント名の文字コード・読めない文字・埋め込み画像・エラー応答を確かめます。
6. **比較の道具**: PoC のスクリプト(pdfplumber を import する `scripts/poc_*`)を削除しました。変更前後の応答を突き合わせる `scripts/compare_dumps.py` を追加しました。

## 移行で変わった出力(ADR 0023 の例外として受け入れたもの)

実際の図面 PDF 3種(ADR 0037 と同じ。A1 判で cid 文字を含む大判図面1ページ、軽量な図面5ページ、埋め込み画像61枚を含むページ)で、変更前後の応答を `scripts/compare_dumps.py` で比べました。

- **原本画像・埋め込み画像**: 全件がバイト単位で一致しました(原本画像 21件、埋め込み画像 3件)。
- **線**: 軽量な図面5ページ(8272個)は全件がバイト単位で一致しました。違いが出たのは次の点だけです。
  - 線幅(大判図面で 46566個): 以前は `w` を実行した時点の値でしたが、描画時の太さになりました(以前は mm の値がそのまま出ていた)
  - 色(埋め込み画像のページで 1849個): Separation 色空間の墨ベタが、白 `rgb(255,255,255)` から `rgb(35,31,32)` になりました
  - 有効数字8桁以上の座標(7個、最大 3.6e-5pt)と、「始点へ戻る `l` と `h`」で閉じた曲線の重複点(1個)
- **テキスト**:
  - 文字・フォント名・サイズ・色(Separation を除く)は、同じ原点の文字で一致しました
  - 単語の外接矩形は、descent の出どころが変わったため全単語で微小に変わりました(埋め込みフォントで最大約 0.001pt、大判図面の一部フォントで最大 0.27pt)
  - 単語の分割がわずかに変わりました(太字表現の重複文字をまとめるため。大判図面で 2235語→2239語)
  - ToUnicode の無いフォントの「□」は、480文字→498文字になりました(差の18文字は、以前は意味のない文字が表示されていた箇所)
- **その他(合成PDFで確認)**:
  - CropBox が MediaBox と異なるページと、MediaBox の原点が 0 でないページで、線・文字の座標が表示範囲の左上原点になり、原本画像と一致するようになりました
  - `v`/`y` 演算子の曲線が正しく描かれ、`polylines` が付きました(以前は崩れて空だった)
  - `w` を指定しないパスの線幅が 0 から 1 になりました
  - 横倍率(`Tz`)のある文字の `sx` に拡大が反映されました
  - xref が壊れたPDFは PDFium が修復して開き、ページツリーが壊れたPDFは 500 ではなく 400 になりました

## 見つかったトレードオフ(受け入れたもの)

- **UTF-8 の CMap**: `UniJIS-UTF8-H`・`UniJIS2004-UTF8-H` で符号化された本文を、PDFium は解釈できません。移行後は「□」(読めない文字、件数つき)になります。以前の pdfminer は読めていました。`UniJIS-UTF32-H` は文字自体は正しいものの、1文字ずつ別の単語になります。`90ms-RKSJ-H`・`90pv-RKSJ-H`・`EUC-H`・`UniJIS-UCS2-H`・`UniJIS-UTF16-H`・`UniJIS2004-UTF16-H` と、5種類の文字コードのフォント名(ADR 0021)は、以前と同じ結果です。実PDF 3種では発生しておらず、ユーザーの判断で既知の制約として受け入れました。該当するPDFが見つかったら対応を検討します。
- **ToUnicode の無いフォントの判定は近似**: ToUnicode があっても珍しい文字ばかりのフォントは、「□」と判定されることがあります。

## 理由

- 速度: `/api/page/lines` の所要時間(`scripts/profile_pages.py`、3回の最小値、JSON 化まで含む)は、大判図面で 4723→1552ms(0.33倍)、軽量な図面で 0.61〜0.70倍、埋め込み画像のページで 113→72ms(0.64倍)になりました。ピークメモリも同等か減りました(大判図面で 387→294MB)。原本画像の描画時間はほとんど変わりません。
- 再現性: 変わった出力の多くは、元の PDF により忠実になる方向です(描画時の線幅、Separation の色、`v`/`y` の曲線、CropBox での位置、横倍率)。
- Lambda: zip は 25.2MB→13.3MB(展開後 67.5MB→42.3MB)になりました。pdfminer.six・cryptography・cffi・pycparser・charset-normalizer が不要になったためです。Lambda は1つの実行環境で同時に1リクエストしか処理しないため、ロックの範囲が広がっても本番で取り合いは起きません。ローカルで同時リクエスト(線データ+原本画像2解像度)を計っても、線データの応答は以前より早くなりました(ADR 0037)。
- 既存の関数を流用した: 線のレコード作成・線幅補正・単語へのまとめ・フォント名の判定は変えていないので、確認済みの挙動を保てます。

### 採らなかった案

- **読めない文字があるページだけ pdfminer で読み直す**: UTF-8 の CMap の本文は以前と同じになりますが、pdfplumber と pdfminer を依存に残すことになり(zip が約12MB 増える)、処理も2系統になるため、ユーザーの判断で見送りました。
- **MediaBox 基準(以前の pdfplumber 互換)の座標を保つ**: 線と原本画像がずれる既存の不具合が残るため見送りました。
- **float32 のまま使う**: PDF に書かれた数値からずれ、全ての線の座標がわずかに変わるため見送りました(10進数への復元のコストは、大判図面で約100ms)。

## 影響

- API の応答が上記のとおり変わります。UI の変更はありません(コメントだけ直しました)。E2E(`pnpm --dir web e2e`・`e2e:parity`)は全件通りました。
- 計測区間が変わりました: `parse` は PDFium による図形と文字の読み取り(内訳 `parse.paths`・`parse.chars`)になり、`texts.cid` は `texts.unreadable` に、メトリクスの `cid_chars` は `unreadable_chars` になりました。
- `src/pdf_unit/raster.py` の `extract_page_images`(バイト列を受け取る版)は計測スクリプト用に残し、サーバーは開いたページを受け取る `extract_images` を使います。
- 今後 PDFium を使う処理を足すときも、文書を開いてから閉じるまでをロックの中に置きます(CLAUDE.md)。
