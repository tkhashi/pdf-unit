# ADR 0049: 全ページのサムネイルが確定したら、Worker 側の文書を閉じる

- ステータス: 採用
- 日付: 2026-10-01

## コンテキスト

[0047](0047-thumbnail-worker-page-cleanup.md)・[0048](0048-thumbnail-close-answers-dropped-jobs.md) の後も、同じ合成PDF(73MB・30ページ)を開くと、先読みが終わった後の Worker のヒープは 79MB だった。そのほとんどは、[0041](0041-thumbnail-client-side-rendering.md) で Worker に渡したPDFの複製(ファイルと同じ大きさ)と、pdf.js のパース結果(フォント等)である。

サムネイルは1ページにつき1回しか要求しない。成功しても失敗しても再要求しない。そのため全ページの要求が確定した後は、Worker 側の文書は使われないまま、文書を切り替えるまで残っていた。

## 決定

- `controllers/thumbnails.ts` で、要求が確定した(描画済み・失敗確定)ページを文書ごとに記録する。全ページが確定したら `closeThumbnailSource` で Worker 側の文書を閉じる
- 文書を切り替えたときの閉じる処理(`controllers/document.ts`)はそのまま残す。先読みの途中で切り替えた場合は、そちらで閉じる。Worker は、すでに閉じた文書をもう一度閉じる要求を無視する

## 理由

- 閉じた後に同じ文書へ描画を要求する経路はない。表示範囲に入ったページの優先度を上げる要求(`reprioritize`)は届くが、Worker 側のキューに該当する要求が無ければ無視される
- 本体側の pdf-lib の文書は、ページの切り出し(サーバーへ送るPDF)に使い続けるので閉じない

## 影響

- 同じ合成PDFで、先読みが終わった後の Worker のヒープは 79MB から 6MB になった。レンダラーの RSS は 0.69GB から 0.61GB になった
- 先読みを終えて文書を閉じた後に、別の文書(同じファイルを含む)を開いても、サムネイルは変更前と同じ PNG で描かれることを確かめた
- 将来、表示倍率の変更などで同じ文書のサムネイルを描き直すことにした場合は、閉じる時機を見直す必要がある
