# ADR 0015: 画面の表記は日本語の表示名にそろえ、操作部品は対象の近くに置く

- ステータス: 採用(開閉ボタンの位置・一括切替の表現・線幅補正の表記は [0016](0016-toolbar-tooltips-and-tristate.md) で変更)
- 日付: 2026-09-25

## コンテキスト

UI/UX レビュー([README](../../README.md) の画面構成)を受けて、ユーザーから次の修正指示があった。

- 属性名のうち linewidth だけが英語なので「線幅」にする
- ヘッダーの「サムネイル」ボタンが一覧から離れていて分かりづらいので、一覧の左側に細長い開閉ボタンとして置く
- アプリ名を「PDF Unit」にする
- 「全体表示」ボタンは不要
- line / rect / curve / text / image の表示チェックを一括でオン・オフするボタンを設ける
- 線幅補正の `fallback_no_samples` などの英語表記が分かりづらいので日本語にする

## 決定

- 属性パネルとクリック巡回のラベルを「線幅」に変更する(両者は同じ属性定義 `STROKE_LEVELS` から作られるので1か所の変更で済む)
- サーバー応答の列挙値(線幅補正の方法 `measured` / `fallback_no_samples` / `fallback_disabled` / `manual`)は、フロントで日本語の表示名に変換して表示する。API の値そのものは変えない
- サムネイル一覧の開閉ボタンは、一覧の左に隣接する幅14pxの縦ボタンにする。向き(`◀`/`▶`)で開閉状態を示し、一覧を閉じても残す。文書を読み込むまでは表示しない
- 「全体表示」ボタンを廃止する。ページ表示時とウィンドウサイズ変更時の自動全体表示のみとし、拡大後に全体表示へ戻す手段は設けない(ユーザー確認済み)
- 凡例の先頭に一括切替ボタンを置く。ボタンの文言は押したときの動作を表し、1つでも非表示があれば「すべて表示」、全部表示中なら「すべて非表示」とする
- アプリ名は画面・タブ・FastAPI のタイトルを「PDF Unit」にする。パッケージ名・起動コマンド(`pdf-unit`)は変えない
- ヘルプ(`?`)の文言は index.html に直書きのまま変更しない(ユーザー確認済み)

## 理由

- 表示名をフロント側で持てば、サーバーの内部名やAPIを変えずに表記だけを改善でき、APIを使う他の処理にも影響しない
- 開閉ボタンを対象の一覧に隣接させると、何を開閉するボタンかが位置で分かる。閉じた状態でも同じ位置に残るので、再び開く場所に迷わない
- 一括切替ボタンの文言を「次の動作」にすると、現在の状態と押した結果の両方が読み取れる

## 影響

- ヘッダーから「サムネイル」「全体表示」の2ボタンが減った
- 凡例の種類名(line / rect / curve / text / image)は抽出元の区別として英語のまま残している
